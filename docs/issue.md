# Автономный локальный переводчик EN→RU (Markdown/txt) для CLI DeepSeek Harness

## Контекст и цель
Нужен автономный Python-скрипт для локального перевода технической документации и файлов репозиториев (`.md`, `.txt`) с английского на русский. Скрипт вызывается через CLI агентом DeepSeek Harness.

Ключевая идея — полностью перенести вычислительную нагрузку перевода на локальный CPU и сэкономить до 99% токенов удалённого агента: агент получает только финальный статус или точечные diff-логи ошибок, а не читает файлы целиком.

## Эталонный источник для проверки

- Локальная фикстура: `tests/fixtures/00-setup-README.md` (239 строк). На ней проверяем корректность перевода (число строк, блоки кода, ссылки, inline-код, таблицы).

## Жёсткие ограничения
- Только CPU (GPU запрещён), ОЗУ ограничено.
- Модель: `Helsinki-NLP/opus-mt-en-ru` (transformers), ~300 МБ весов.

## Функциональные требования
1. **Перевод строка-в-строку.** Число строк на входе и выходе строго совпадает. Пустые строки и строки только из спецсимволов/пробелов копируются без вызова модели.
2. **Пропуск блоков кода.** Конечный автомат `in_code_block`; строки между тройными бэктиками (и сами ограничители) копируются без перевода.
3. **Защита inline-элементов.** Инлайн-код (одинарные бэктики), HTML-теги и Markdown-ссылки изолируются уникальными плейсхолдерами (например `__INLINE_CODE_0__`). В ссылках переводится только текст в `[...]`, URL в `(...)` не меняется. После перевода плейсхолдеры возвращаются на место.
4. **Локальная валидация.**
   - *Blind:* сверка числа строк и возврата всех маркеров; при успехе — `[VALIDATION SUCCESS] Файл <имя> успешно проверен локально. Структура сохранена.`
   - *Diff-Error:* при аномалии (пропал маркер, сломался inline-код, пустая строка при непустом оригинале) строка пишется в diff-лог; в конце выводится `[VALIDATION WARNING] Обнаружены ошибки в следующих строках: Строка 45: <оригинал> -> <перевод>`.
5. **CLI.** `--file <path>` и `--dir <path>` (рекурсивно `.md`/`.txt`). Вывод с постфиксом `_ru` (`README.md` → `README_ru.md`). Файлы, уже содержащие `_ru`, пропускаются. Подробное логирование в stdout.
6. **Замеры времени.** Логировать wall-clock: задержку на строку, время на файл и суммарно на `--dir` (`[TIMING]`). Токены основной модели пока не замеряем (основная модель исключена из этапа).

## Критерии приёмки (Definition of Done)
- [ ] `--file` и `--dir` работают; `_ru`-файлы корректно именуются и пропускаются.
- [ ] Число строк совпадает на тестовых файлах (пустые строки, блоки кода, CRLF, отсутствие завершающего перевода строки).
- [ ] Блоки кода копируются дословно, модель для них не вызывается.
- [ ] Inline-код, HTML-теги и URL ссылок переживают перевод без изменений; текст ссылок переведён.
- [ ] Логи `[VALIDATION SUCCESS]` / `[VALIDATION WARNING]` выводятся по спецификации.
- [ ] При аномалии скрипт не падает, а пишет diff-лог и точечный отчёт.
- [ ] Работает offline после первого скачивания модели; пиковое ОЗУ в пределах CPU-бюджета.
- [ ] `requirements.txt` (CPU-only torch) и инструкция по установке/запуску.
- [ ] Перевод эталонного файла `tests/fixtures/00-setup-README.md` проходит проверку (число строк, блоки кода, ссылки/inline-код/таблицы сохранены).
- [ ] Логируется wall-clock (на строку, на файл, суммарно на `--dir`).

## Основные риски (подробно в docs/handoff.md)
- Плейсхолдеры могут не пережить MarianMT (SentencePiece) — нужен прототип и fallback.
- Установка зависимостей тяжёлая (torch CPU), модель ~300 МБ скачивается один раз.
- Качество перевода построчно ниже, чем по предложениям (нет контекста).
