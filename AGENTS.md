# AGENTS.md — правила работы в репозитории (читать ПЕРВЫМ)

Правила обязательны для любой сессии (Lead и фазовых). При противоречии с другими файлами — приоритет у этого файла.

## Режим работы
- Первый подход: **каждый issue / каждая фаза — отдельная сессия**, которой управляет пользователь.
- Пользователь контролирует каждое изменение, чтобы отслеживать, как работает инференс локальной модели. Агент не выполняет работу «вперёд» без команды.

## Роли
- **Lead-сессия** готовит и ведёт общие артефакты (`AGENTS.md`, `HANDOFF.md`, `docs/plan.md`, `docs/handoff.md`, фича-issue #1).
- Lead **не выполняет фазы** и **не заводит issue на будущие фазы заранее**; агентов для фаз — **спавнит**.

## Issue на фазу
- Одна фаза = один issue.
- Issue на фазу создаёт **сессия-исполнитель этой фазы в момент старта** (не Lead заранее).
- По завершении фазы issue закрывается.

## Git
- Коммитить — можно.
- Пушить в `master` напрямую — **нельзя**.
- Пуш — только в feature-ветку; мерж в `master` — только через **PR**, который ревьюит и мержит пользователь.
- **После фазы (если был пуш в feature-ветку) — обязательно создать Pull Request** в `master`.

## Хэндов-ритуал
- **Старт сессии** (в этом порядке): `AGENTS.md` → `HANDOFF.md` → `docs/plan.md` → `docs/handoff.md`.
- **Конец фазы**: обновить `HANDOFF.md` (статус, решения/факты, отклонения), закоммитить и **создать Pull Request** в `master`.

## Ответственность файлов (не дублировать)
Каждый файл содержит только своё:
- `AGENTS.md` — правила работы (этот файл).
- `HANDOFF.md` — живое состояние: статус, решения/факты, отклонения, журнал фаз.
- `docs/plan.md` — план: эталон, исполнители (коды PH/FH/PL/FL), фазы, структура кода, критерии.
- `docs/handoff.md` — статичный справочник рисков/камней.
- `docs/issue.md` — локальное зеркало фича-issue #1.
- `README.md` — краткое «что это за проект».
